今天大家很喜欢用“智能驾驶”来想象企业 AI。理想状态里，未来的企业系统也应该像一辆越来越聪明的车：能够感知环境、理解目标、规划路径、处理异常，并随着能力提升逐渐减少人的介入。

这里有一个关键点经常被忽略。智能驾驶从来不是“模型足够聪明以后，车就可以直接在现实世界里裸奔”。且不说智能驾驶本身还分从 L1 到 L5 的不同等级，即使讨论更高程度的自主驾驶，它背后也始终依赖定位、数字地图、导航、环境建模，以及对实时状态的持续感知。

地图本身也不是一张固定比例的平面图。开长途时，我们关心的是城市、区域和道路网络；进入具体路口以后，视野会自然放大到车道、转向关系和局部环境。导航系统不断 zoom in 和 zoom out，在不同分辨率之间切换，因为同一个现实世界，在不同决策尺度下，需要呈现的信息本来就不同。

车变得越来越智能，并没有让地图消失。

恰恰因为它开始自主行动，“我在哪里、周围是什么、哪些地方可以到达、目标在哪里、下一步会把我带向哪里”这些问题才变得更加重要。

企业 AI 面临的是同一类问题。

今天我们讨论模型能力、Agent、harness、知识库和上下文工程，已经花了很多精力研究 AI 怎么推理、怎么执行、怎么形成闭环。但在这些问题下面，还有一个更基础的问题没有被充分讨论：

AI 应该生活在一个什么样的业务世界里？

我把这个东西叫作企业业务地图。

## 从 POI、道路到实时路况

继续沿用地图的比喻，会很容易理解一张企业业务地图里应该有什么。

城市地图上有医院、机场、餐厅、地铁站，这些是可以被稳定指认的 POI。企业也有自己的“POI”：客户、合同、订单、项目、产品、设备、物料、供应商、任务……这些相对稳定存在、能够被识别和引用的东西，就是业务对象。

但只有 POI 还不能形成地图。地图真正有用，是因为这些位置之间存在道路和拓扑关系。

企业里的对象也是一样。一个项目不会孤零零地存在于某个“项目管理模块”里，它承接某份合同和客户承诺，又会进一步关联交付物、产品、物料和任务。一个采购任务也不只是一张采购页面里的单据，它可能来自某个项目的物料缺口，连接供应商和采购订单，并最终影响项目能否按期交付。

所以可以把业务对象理解成地图上的 POI，把对象关系理解成连接它们的道路网络。哪些对象能够相连，一个变化会沿着什么关系向外传播，一个动作最终可能影响到哪里，都取决于这张地图的结构。

道路之外还有交通规则。单行线不能逆行，某些地方不能掉头，不同车辆拥有不同的通行权限。企业里同样存在权限、业务规则、前置条件、合规要求，以及某些动作必须经过的路径。这些规则和约束共同定义了哪些行动可行。

最后是实时路况。今天某条路拥堵、某个出口临时关闭，在企业里对应的可能是订单延期、库存不足、供应商失约、设备异常或者任务超期。它们变化得很快，却都必须附着在一个相对稳定的业务结构之上才有意义。

因此，企业业务地图至少包含两个不同层次：业务对象、关系、规则和约束构成相对稳定的地图；对象当前的状态则像持续变化的实时路况。AI 真正进入业务世界工作，需要同时理解这两层。

## 地图让行动发生在一个可以理解的空间里

假设把一个人扔进完全陌生的城市，只告诉他去 B 点。没有地图，他也不是绝对到不了。可以看路牌、问人、尝试不同方向，走错以后再退回来；时间足够长，甚至可能逐渐摸清整座城市。

麻烦在于，在这个过程中，每走到一个岔路口，他凭什么知道自己离 B 更近了还是更远了？

如果只有最终结果作为反馈，那么大量中间行动都只能得到同一个信号：“还没到。”他当然可以走完无数条路径以后，再根据成功和失败慢慢总结规律，最终在脑子里形成关于哪些地方相连、哪些方向更有希望的判断。

某种意义上，这就是用环境和交互成本，逐渐摸索出一张隐式地图。

强化学习就是在做类似的事情。智能体通过大量探索、奖励和反馈，逐渐学习某种状态下采取什么动作更可能获得好的结果，理论上完全成立。但如果一个世界的结构原本可以被显式表达，那么完全依赖这种方式，就意味着要用大量交互去重新逼近那张地图。

真实企业并不是一个可以无限重开的 simulation。一次采购错误、一次报价失误、一次遗漏的合规要求，都有真实成本；更麻烦的是，许多业务结果要几周甚至几个月以后才出现，到那时要准确判断今天的结果究竟来自之前哪个动作，本身已经非常困难。

有地图以后，问题就简单得多。行动者先完成定位，再理解当前位置、目标和整体结构之间的关系。哪些路径根本不可达，哪些路线表面上绕远但整体成本更低，都可以在行动之前开始判断。

地图没有替智能做决定，它只是把行动放进了一个可以规划的空间。

这也是为什么我觉得，AI 和人真正合理的关系更像“地图 + 自动导航”。人在拥有地图的时候，本来就可以自己推演路线，只是速度慢，也更依赖个人经验；AI 加入以后，相当于在同一张地图上增加了一个高性能导航系统，可以更快地比较路径、推演结果、识别风险。

AI 提升的是计算和决策能力，地图提供的是被计算的世界。

## 多主体协作天然需要共享地图

如果企业里永远只有一个人或者一个 Agent，“它能不能靠自己慢慢把世界学出来”还只是一个效率问题。现实企业却天然是一个多主体协作环境。

一份合同从签署到完成交付，可能同时涉及销售、研发、采购、生产、财务和管理者。现在我们又准备往这个协作网络里加入销售 Agent、采购 Agent、排产 Agent 和经营分析 Agent。主体越来越多以后，一个比导航更加基础的问题就出现了：这些不同的智能如何确认，彼此讨论的是同一个业务世界？

《人类简史》里有一个很有启发性的观点。人类能够建立远远超过小群体规模的大规模协作，很重要的一个原因，是我们能够共同相信和使用一套主体间共享的现实。金钱是其中最典型的例子：一张纸币或者银行账户里的一串数字并没有天然的物理价值，但因为大量彼此陌生的人都承认它背后的意义和规则，它就可以组织极其庞大的经济活动。

公司、法人、合同、股权、岗位也具有类似的性质。一份合同在物理意义上不过是几页纸或者一组电子记录，但只要参与者共同承认“这份合同已经生效，并产生了这样的权利、责任和交付承诺”，它就足以驱动整个组织开始行动。

从这个角度看，企业本身就是一套建立在共享业务现实之上的协作系统。ERP、CRM、OA 等数字化系统，过去其实已经承担了其中一部分工作：它们让合同、客户、订单、审批这些原本散落在人脑和纸面上的业务概念拥有了共同的数字载体。

只是过去参与这个世界的智能主体主要是人。今天，硅基智能也开始进入同一个协作网络。

于是，当一个人说“这个项目有风险”时，无论接下来处理它的是另一位同事还是一个 Agent，都需要知道“这个项目”准确指向哪个业务对象，并能够继续沿着它和合同、交付、物料、任务之间的关系往下理解。当采购 Agent 把异常交给采购人员时，双方还需要共享企业里的采购规则，知道什么情况需要审批、什么动作可以执行、边界在哪里。

这些东西过去有一部分存在于数字化系统里，另一部分存在于人的经验和各种非结构化文档中。Agent 进入以后，单纯依靠 harness 临时拼装上下文会越来越吃力，因为协作需要的已经不只是“这一轮对话应该给模型哪些信息”，还包括一套更加稳定的、能够被人和 AI 共同指认的业务语义。

这就是企业业务地图作为公共坐标系的意义。

## 共享地图，不等于所有人看到同一个页面

这里很容易产生一个误解：如果所有主体共享同一个业务世界，是不是意味着销售、采购、老板和 Agent 最后都要面对一张巨大复杂的对象关系图？

现实地图恰好可以帮助我们理解为什么不会这样。

同一个东京，游客打开地图时关心景点、酒店和交通线路，开车的人关心道路、拥堵和停车场，城市规划者看到的又会是区域、人口和基础设施。大家依赖的是同一座城市，却不会使用完全相同的信息视图。

企业也是一样。共享的是底层世界，视图则应该随着主体、任务和当前状态变化。

老板可能先从经营层看见几个核心目标和受到威胁的项目；发现其中一个项目异常以后，可以下钻到项目履约，再继续放大到某个交付物，最后定位到一个具体的缺口物料和采购任务。采购人员的观察路径可能恰好相反：他从供应商延期这个局部异常出发，沿着对象关系向上 zoom out，判断它最终会影响哪个项目、哪份合同，甚至哪个经营目标。

这就像数字地图的缩放。远距离规划时，我们不需要看见每一条车道线；真正进入复杂路口以后，城市级信息又会退到背景，局部结构成为重点。

所以这里的“分辨率”并不只是界面多显示几个字段或者少显示几个字段，它意味着我们正在以什么尺度理解同一个业务世界。

而一个好的企业 AI 工作台，也不应该只是传统意义上按角色预先做死的门户。它应该能够结合当前主体、当前任务和实时状态，动态判断此刻什么信息最重要。同一个项目平时在老板眼里可能只是经营组合中的一个节点，但一旦关键物料延期，它就应该自动获得更高的信息权重；同样一个对象，在采购、销售和经营者眼里也可以呈现完全不同的局部信息。

底层地图保持一致，上层视图不断动态裁剪。

共享地图从来不要求所有人看到同一个页面。它要求不同的人和 Agent 所看到的不同切面，能够重新映射回同一个业务世界。

## 地图决定了什么才是有效的 context

沿着这个逻辑再往下走，今天 Agent 落地里很热的 harness 和 context 也可以换一个角度理解。

现在很多做法会自然滑向“给模型更多信息”：上下文不够，就塞更多文档、更多历史对话、更多数据库记录。但导航系统从北京开到上海，并不会把中国所有城市的 POI、每一条小巷和全部实时路况同时扔到驾驶员眼前。

地图真正有价值的地方，在于它允许系统根据当前位置和目标不断裁剪相关空间。

企业 AI 也应该如此。某一次决策需要知道的，未必是整个企业发生了什么，而是此刻应该把业务地图裁到哪里、采用什么分辨率、沿着哪些关系展开，以及哪些实时状态真正会影响当前目标。

这样看，业务地图和 context 其实属于上下两层。地图维护完整而相对稳定的世界结构，context 则是某个主体为了完成某一次任务，从这张地图和当前状态中动态裁出的一块局部世界。

没有底层地图，每次构造 context 都容易重新从原始资料里猜“什么相关”；有了地图，context 才有机会变成一种可计算的裁剪。

## 协作的关键，是让业务世界保持连续

今天企业里的很多协作之所以看起来非常随意，是因为大量上下文实际上存放在人脑里。一个熟悉项目的人听到“这个项目你关注一下，供应链可能有问题，转采购处理”，往往已经可以自动补全这句话背后的对象、责任关系和前因后果。

这种能力来自他长期工作以后在脑中形成的隐式业务地图。

当协作主体开始混合成人和 Agent，甚至多个 Agent 时，每一次交接都重新依赖自然语言补全上下文，成本就会迅速放大。真正稳定的交接应该能够落到业务地图上的明确位置：某个项目中的一项交付因为某个物料缺口受到影响，这个缺口关联到当前超期的采购任务，因此需要新的责任主体介入。

接手的人是谁可以变化，Agent 也可以变化，但他们进入的是同一个业务位置。处理完成以后，结果继续更新原来的对象状态，下一位参与者不需要重新从一堆聊天记录里猜发生过什么。

这样一来，一条工作链路虽然不断更换执行主体，业务世界本身却是连续的。

我觉得这才是人机协作真正应该追求的状态。协作不要求所有主体拥有同一个界面，也不要求大家把所有上下文装进脑子；它要求每一次沟通和行动都能够落回一个共同的业务坐标系。

## 有了坐标，经验才可能变成组织记忆

企业每天都在产生大量“经验”：会议纪要、项目复盘、邮件、聊天记录、异常处理和审批意见。但这些东西被记录下来，离真正成为组织能力还有很远。

一次项目延期留下十页复盘文档，当然包含很多有价值的信息。到了下一个项目，真正困难的问题却是：今天发生的情况和上一次究竟哪里相似？

如果过去那次经验能够挂回稳定的业务对象，它就拥有了坐标。我们可以知道它发生在哪个项目，涉及什么产品和物料，与哪个供应商相关，当时哪个任务发生了什么变化，又是通过怎样的关系最终影响了交付。下一次出现类似的结构，过去的经验才有机会被真正调用。

否则所谓的“企业知识”很容易变成一个越来越大的文本仓库。

这也是为什么我一直对“把企业所有文档交给 AI，它自然就会学会业务”这件事比较怀疑。想想一个人类新员工就知道了：给新人发 SOP、历史项目、会议纪要和几千封邮件，他当然可以很快了解大量事实，但没有哪个公司会认为网盘权限一开，onboarding 就结束了。

真正困难的内容往往藏在资料之间：哪些规则仍然有效，当前目标为什么是这个，一个对象为什么影响另一个对象，出现冲突时谁应该判断，一个局部动作为什么最后会影响整体结果。

AI 可以把“阅读十万页资料”的成本压得极低。可如果十万页材料背后的世界没有被组织起来，它得到的依然只是十万页材料。

读得更快，并不会自动生成地图。

## AlphaZero 从来没有生活在一个没有地图的世界里

围棋是另一个很好的对照。

AlphaZero 经常被用来说明，AI 可以摆脱人类经验，通过自我博弈学出极强的策略。这当然成立，但围棋同时拥有一个企业世界很难奢望的条件：它的世界结构清晰得惊人。

棋盘在哪里，棋子是什么，哪些动作合法，一个动作以后状态怎么变化，什么时候结束，什么叫赢，这些都已经被完整形式化。

所以 AlphaZero 可以把巨大的学习能力集中在“棋应该怎么下”这个问题上。它不需要从棋谱、聊天记录和历史数据库里先猜几年“围棋到底是什么”。

这一区别非常重要。

围棋里的策略学习，发生在世界已经被高度建模之后。

企业 AI 今天遇到的很多困难恰恰还停留在更前面：几个系统里的“订单”究竟是不是同一个概念，一个项目和一份合同是什么关系，哪些属性真正属于对象自身，哪些只是历史流程留下的字段，哪些规则长期有效，哪些只是此刻发生的状态变化。

如果这些结构还很模糊，就要求 Agent 自己学习最优策略，有点像让棋手一边下棋，一边猜棋盘的边界和游戏规则。AI 再强，这部分成本也不会自动消失。

## AI 可以参与画地图，但企业很难没有地图

当然，我并不认为未来的企业业务地图应该靠人吭哧吭哧一笔一笔维护。AI 完全可以参与其中：帮助发现对象、识别候选关系、检查模型冲突、发现规则变化，也可以随着业务演化不断辅助修正我们对企业世界的表达。

地图本身也不会一次完成。业务会变化，我们对业务的理解同样会变化。

所以真正值得讨论的，并不是“人工建模还是 AI 自动学习”这个二选一问题，而是哪些相对稳定的世界结构值得显式保存，哪些动态判断和策略适合交给智能去学习。

当企业里越来越多行动由 AI 参与完成，一套共享、可寻址、可缩放的业务世界结构只会变得更加重要。

对象是这张地图上的 POI，关系构成道路和拓扑，规则定义通行方式，动态状态形成实时路况。不同的人和 Agent 从同一个世界里获得不同视图，需要理解全局时 zoom out，准备解决具体问题时 zoom in。一次行动改变现实以后，新的状态重新回到地图，过去的经验也因此能够找到自己的坐标。

人类社会已经证明，大规模协作离不开共享的对象、规则和意义。未来企业只是多了一类新的参与者：一部分智能是碳基的，另一部分是硅基的。它们不必用完全一样的方式理解世界，更不需要看到完全一样的页面，但只要想长期协作，就需要存在一个能够互相映射的公共坐标系。

所以我越来越觉得，企业 AI 时代真正值得建设的基础设施之一，可能既不是一个无限膨胀却缺乏结构的知识库，也不只是一个越来越强的 Agent。

而是一张碳基与硅基智能能够共同指认、共同理解，并且可以在不同分辨率下共同工作的企业业务地图。
