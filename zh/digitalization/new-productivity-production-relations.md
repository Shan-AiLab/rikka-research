假设汽车刚刚发明，投资人给创业公司提出一个要求：

**「你这辆汽车必须可以直接替代一匹马，什么地形都能走，而且单次运输成本必须比马便宜。」**

不允许修公路，不允许建设加油站，也不允许重新设计运输网络。

听起来很荒谬。但今天不少企业 Agent 的商业模式，正在遵循类似的逻辑：一个采购 Agent 替代一个采购岗位，一个销售 Agent 替代一个销售岗位，再试图证明 Agent 的成本低于人工。

**汽车必须按照马的使用方式证明经济性，Agent 必须按照现有岗位的工作方式证明经济性。**

问题在于，汽车的价值不只是用发动机替换马匹。它需要道路、交通规则、能源供应和维修网络，也催生了新的运输方式与物流组织。

汽车改变了运输能力，也推动了基础设施、分工和协作方式的重构。

AI 是否正在面临同样的问题？

## 一、新生产力，不只是替代旧生产工具

以岗位为单位设计 Agent，是一种自然的产品思路。企业已经在为这些岗位支付人力成本，如果 Agent 能完成相同工作且成本更低，经济价值就容易解释。

但这里隐含着一个前提：**现有岗位所承担的工作，仍然应该以同样的方式组织和完成。**

岗位并不是业务天然存在的基本单位，而是组织在特定生产力条件下，对职能与责任的一种组合安排。

例如，一位采购人员同时承担需求核实、供应商询价、订单执行、交期跟进和异常协调。其中有些工作来自业务本身，有些则是为了适应当前的信息条件与组织方式。

如果订单、物料、供应商和交付需求之间缺乏稳定关联，采购人员就需要反复查表、问人、核对状态。

按照这个岗位的全部工作设计 Agent，就要求它具备业务判断、跨系统操作、信息检索和大量沟通协调能力。于是我们不断强化 Harness、Memory、Context 和工具调用机制，希望 Agent 能适应现有环境。

这就像要求汽车成为一辆能在任何泥地里行驶的全地形车。

但如果改变业务环境，让对象关系、规则和实时状态能够被系统稳定维护，部分工作就不必反复执行。剩下的职能，也可以重新分配给人、AI 和数字化系统。

**新生产力不仅可能替代旧分工中的执行者，还可能改变分工本身。**

## 二、要重新组织生产，首先需要理解业务

新的分工方式不能凭空设计。

企业在价值链中承担什么功能？需要完成哪些业务？依赖什么资源、规则与协作？只有回答这些问题，才有依据判断哪些工作可以自动化，哪些职能可以重新组合，哪些任务可以取消。

这也是[《企业 AI 落地为什么必须从业务开始》](https://rikkalab.com/zh/digitalization/enterprise-ai-starts-with-business/)中提出的依赖关系：

**业务 → 组织 → 系统 → Agent。**

业务定义需要完成什么，组织安排谁来承担，系统承载业务对象与运行规则，Agent 才能在其中行动。

但这条链不意味着现有组织结构必须保持不变。

过去，企业通过部门分工、流程审批和层层汇报协调复杂业务，也因此产生大量信息传递、状态核对和沟通成本。

当业务对象、关系、规则和状态能够被共享，部分协调工作就可能转化为系统能力。原来分属不同部门的职能可以重新组合，职责边界和管理方式也可以相应调整。

AI 不意味着部门必然减少，新的风险与治理要求也可能产生新的职能。

关键在于，**组织结构应该根据业务需要和新的生产条件设计，而不是直接成为新生产力的固定边界。**

## 三、AI 原生组织，需要怎样的运行环境？

AI 原生组织与传统企业 AI 改造的区别，不应该简单归结为使用了多少 Agent。

一家企业可以部署大量 Agent，却仍然按照原有部门、岗位和系统边界组织工作。每个 Agent 都在局部提效，完整业务仍需要跨系统、跨部门反复交接。

另一家企业可能只使用少量 Agent，却从业务出发，重新设计职能、责任和协作方式。

**AI 原生组织的关键，不是把 AI 安装进旧组织，而是围绕新的智能能力进行组织设计。**

但组织设计需要运行环境支撑。

如果业务对象分散在不同系统，规则藏在文档和人脑里，状态依靠人工同步，即使重新分配了职能，人和 AI 仍然难以稳定协作。

一种值得探索的 AI 原生系统，是将业务对象、关系、规则、状态和责任作为共享基础，使不同参与者能够持续理解并改变同一个业务世界。

目前常见的语义层和知识图谱，更多聚焦于概念、数据口径和对象关系，往往缺少对组织职能与责任分工的明确建模：谁对什么负责，拥有怎样的决策权和行动权，任务如何交接。只有业务结构还不够，还需要能够运行的组织结构。

[Palantir 的 Ontology](https://rikkalab.com/zh/digitalization/software-boundaries-enterprise-os/) 已经尝试将数据、逻辑和行动连接到业务对象上。但具备行动接口，不等于自动定义了组织责任；模型能否贯穿实际执行、多个 Agent 能否接续同一项业务，仍然需要解决。

这既是技术问题，也是组织问题：谁负责业务定义？谁维护共同规则？谁有权调整系统边界和职责分配？

传统企业拥有业务积累，却可能受制于组织惯性和既有系统。新成立的 AI 原生企业拥有更大的设计空间，却仍需建立真实业务能力。

**真正的区别，在于组织有没有能力和权力持续定义业务、调整分工、改造运行环境。**

如果只能增加 Agent，却无法改变环境，上游未解决的复杂度就只能继续由 Agent 承担。这也是[《为什么 Agent 做着做着就做不动了？》](https://rikkalab.com/zh/digitalization/why-agents-stall/)所讨论的问题：当大家忙着制造更强的全地形车时，是否也该考虑修路？

## 四、新生产力创造的价值应该如何衡量？

假设下面几种情况同样消耗了 100 升油：

- 有人沿着高速公路运送了 100 吨货物。
- 有人在泥地里挣扎了半天，终于抵达目的地。
- 有人在原地打滑，哪儿也没去。
- 还有人在修路，让以后所有车辆都能顺利通过。

类似地，同样的 Token 消耗，可能意味着高效完成任务、反复恢复上下文、无效重试，也可能用于业务建模、规则沉淀和环境建设。

**油耗不是运输效率，Token 消耗量也不是 AI 生产力。**

更重要的是，修路的价值不只是降低运输成本。挖掘机、压路机可能比汽车更耗油，但道路不仅让原有运输更高效，还让过去难以抵达的地区变得可达，使物资调度、公共服务和应急救援成为可能。

即使车流稀少，一条道路也可能大幅提升整个区域的连接与治理能力。

企业数字化也是如此。明确业务对象、状态、规则和责任，不仅可能减少重复推理与人工协调，还能让组织看见过去看不见的业务、追踪过去无法定位的问题、协调过去难以组织的资源。

这正是[《数字化的本质，是提升复杂系统的治理能力》](https://rikkalab.com/zh/digitalization/digitalization-governance-capacity/)讨论的核心：**降本增效只是结果之一，更根本的是让组织能够治理过去无法治理的复杂度。**

因此，评价 AI 带来的价值，不应局限于单个 Agent 的投入产出，还需要考虑整个业务系统的效率、质量、风险控制、治理能力，以及由此打开的新的价值创造空间。

这里有一个值得验证的命题：

**新生产力创造的价值，未必能在旧生产关系划定的边界内得到完整衡量。**

如果只用单次运输收益评价公路，就会忽略交通网络创造的经济与社会价值；如果只用岗位替代成本评价 AI，也可能忽略组织分工重构、共享环境建设和治理能力提升带来的收益。

**新的生产力不仅可能提高原有工作的效率，还可能改变我们能够完成什么，以及能够以什么规模和方式组织生产。**

## 五、从企业 OS 到产业 OS：分工的重构不会止于企业内部

如果 AI 可以改变企业内部的岗位、职能和部门分工，也可能进一步改变企业之间的分工。

企业边界同样受到生产能力、交易成本和协作条件的影响。

过去，一项职能需要在企业内部完成，可能是因为外部协作成本太高；不同企业重复维护业务规则，可能是因为缺少共同的数字基础；上下游依靠大量文件与人工沟通，可能是因为彼此无法持续共享可信的业务状态。

当这些条件改变，原有分工就有了重新设计的空间。

例如，产品资料核验、供需匹配、交付追踪等跨企业重复发生的工作，能否部分转化为共享的产业能力？不同企业的人和 Agent，能否围绕共同的业务对象、规则与状态持续协作？

这需要解决数据权限、责任划分、商业利益和信任问题，而不只是连接几个 API。

企业 OS 可以看作对企业内部共享业务环境的一种探索。进一步将可复用的行业定义、规则和协作能力延伸到企业之间，就可能走向[产业 OS](https://rikkalab.com/zh/digitalization/enterprise-os-to-industry-os/)。

它的潜在价值不仅是减少重复建设，更是为新的产业分工提供基础。

这条路径不必从建设完整平台开始。可以从真实业务的局部闭环逐步扩展，让经过验证的结构与能力被更多参与者复用。

## 结语｜从替代马匹，到重建交通网络

想象一家企业不再主要依靠人盯着系统和群聊推动业务。

客户在群里提出交期变更，Agent 识别要求并关联到具体订单和交付项。系统找到受影响的物料、生产计划和供应商承诺；AI 评估可行方案，明确规则能够处理的部分自动执行，需要改变商业承诺时交给有权决策的人。

决策形成后，任务分配给合适的人或 Agent，执行结果持续更新业务状态。下一位参与者不必重新询问背景、核对数据。

随着这种能力发展，部分信息搬运、重复核对和流程协调工作可能消失。原来固定在岗位里的职能可以重新组合，较小的团队也可能管理更复杂的业务。

当协作延伸到上下游企业，原本分散在不同组织中的任务有机会基于共同的业务环境接续。企业可以更专注于自己的优势环节，利用共享能力参与更复杂的产业网络。

这可能催生新的组织形态：**人和 AI 围绕业务目标动态分工，组织根据生产需要持续调整，共享数字环境承担越来越多的连接与协调工作。**

这些变化仍需要通过真实业务验证，但它们展示了一种不同于岗位替代的生产力发展路径。

**汽车最终改变的不是养马的成本，而是人类运输、生产与生活的整个空间。**

释放 AI 生产力，也可能不只是让企业用更少的人完成同样的工作，而是让我们能够完成过去难以完成的任务，建立过去难以维持的协作，让更多的人与智能共同创造价值。
